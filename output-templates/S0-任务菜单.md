# S0 任务菜单展示（安装完成后 · 唯一要展示的菜单）

> **展示时机**：安装/学习阶段结束后。**不得**索取产品、市场、官网、昵称、token。
> **格式铁律（2026-09-10 用户拍板）**：菜单**必须逐行 + emoji 突出 + 标注 ⭐推荐**。
> 旧版把编号压成 `①②③④⑤⑥` 连成一行 → 用户看不出该选哪个，**违例**。
> **★项数铁律（2026-09-10 用户追问后收紧）**：**只列 4 项，且按当前状态裁剪**。
> 6 项时新用户会看到「继续项目（无）」「刚装完就更新」这类**用不上的项**——既造成选择困难，又显得不专业。

## 有旧项目时（推荐「继续以前的项目」）

```
✅ 安装完成，环境自检通过。你现在想做什么？

  1. 📂 继续「<项目名>」（当前：<节点>）  ⭐推荐
  2. 🚀 开始一个新的获客项目
  3. 🌐 用我的官网、产品页或目录提炼资料
  4. 📖 先了解完整流程

回复编号即可（如「1」）。
```

## 无旧项目时（推荐「开始新的获客项目」）

```
✅ 安装完成，环境自检通过。你现在想做什么？

  1. 🚀 开始新的获客项目  ⭐推荐
  2. 🎯 先判断我的产品适不适合
  3. 🌐 用我的官网、产品页或目录提炼资料
  4. 📖 先了解完整流程

回复编号即可（如「1」）；只是先看看就回「4」。
```

## AI 执行要点与边界

- **★只列 4 项（项数铁律）**：菜单项数上限 4。禁止把 5-6 个动作平铺——用户实测反馈"选项多了会选择困难"。要加新动作时，先问"能不能并进现有 4 项之一"
- **★按状态裁剪**：**无旧项目时不显示「继续项目」**（列一个"（无）"是纯噪音）；**不显示「更新/换机」**（刚装完就让人更新，逻辑矛盾）
- **不在菜单位的动作**：更新系统、换电脑继续 → 用户主动说"更新""换电脑"时直接命中 `../SKILL.md` 路由表触发词，**不必占菜单位**
- **★逐行展示**：每项**独立一行**，禁止压成一行或用 `①②③` 连写（用户截图反馈"1234 不明显"）
- **★emoji 突出**：每项前一个 emoji（🚀🎯🌐📂📖），稳定一致，让用户一眼扫到
- **★必须标注推荐**：用 `⭐推荐` 明确标出该选哪个——有旧项目推荐①，无旧项目推荐①（开始新项目）；有旧项目菜单里①是"继续项目"。**不标推荐 = 违例**
- **★推荐是建议不是代选**：标了推荐仍等用户回复编号，不得替用户选、不得默认进入 S0
- **结尾给最短回复指引**：一句"回复编号即可（如「1」）"，降低回复门槛
- **★此阶段禁止**：问产品/市场/官网/昵称/token；默认建新项目
- **用户选具体任务后**，才按 `../SKILL.md` 对应路由渐进询问；只有选「开始新的获客项目」才问纯个人昵称 + 一句话产品
- **emoji 使用边界（易混）**：**本菜单/聊天话术鼓励用 emoji 突出**；但**邮件正文**禁 emoji 堆砌（`specs/sequence-config.md` 视觉扫读铁律：≤1 个且仅当品类天然适配）——两处规则不同，不要混用
