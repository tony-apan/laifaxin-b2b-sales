# S6-数量账 · 保存结果透明解释（用户问"怎么才存了这么点"时用）

```
✅ 进度：第 3 步 / 共 6 步
现在：保存完了，**存完即发**数量账（为什么邮箱比公司少）
🎯 该回什么：**不用回**；有疑问直接问我

【保存结果对账】按您的确认，本次共保存：

| 项目 | 数量 | 说明 |
|---|---:|---|
| 您确认保存 | **<N> 家** | 这是您点头的家数 |
| 实际保存成功 | **<X> 家** | 没存上的我会单独列出原因，问您要不要补存 |
| 本次新增邮箱 | **<M> 个** | 去重后真正新增的联系人邮箱 |
| 平均每家邮箱 | **<e> 个/家** | 以往批次大约 **1.5 个/家**（历史数据，仅供参考，不代表这批）|

**为什么搜到的公司不少，最后存下的邮箱却没那么多？** 下面几条我会**先讲这次实际发生的那条**，再补一句其他可能相关的：

1. **每公司上限 3 个邮箱**（您确认过的设置）：一家公司就算有 10 个联系人邮箱，也只存最好的 **3** 个——防止对同一家公司过度触达。想存更多可以上调（**3→6→9**），但会多消耗点数（平台用量额度）。
2. **平台会先核对邮箱真假**：明显无效、格式错的会剔除；暂时查不到真假的，也会先帮您存着。
3. **以前存过的邮箱不重复算**：重复保存显示 **0** 是正常的。
4. **邮箱是平台陆续补出来的**：公司先存进客户列表，邮箱随后逐步补齐。任务显示完成后，邮箱数还会随时间小幅增加。

📊 **对照参考**：以往批次观测大约 **1.5 个邮箱/家**（历史数据，仅供参考）；低于 **1.0** 通常是该买家类型的邮箱覆盖偏弱，可考虑换一个更精准的搜索起点。

本次数据在平台的这个页面能查：<平台页面链接>

**您可以做的**：想核对就点上面的链接看一眼；数字对不上、或觉得邮箱太少，直接问我，我帮您查原因。
**下一步**：我开始写开发信草稿，写好后先给您看，确认了才批量生成。

🎯 该回什么：不用回；数字不对直接问我。
```

## AI 执行要点与边界
- 保存完成**立即发**本卡，不等用户追问；四机制按实际发生解释，只讲确实发生的
- 数量口径：`contactSaveCount` 是**去重后新增**邮箱数，用于对账；`companySaveCount` 是任务进度计数（=total，非去重），不得当"新增公司数"或"全部入库"说。必须展示 确认 N → 实存 X 的差额及原因
- 若用户问"能不能多存"：可解释 3→6→9 阶梯与点数代价（marketing-rules-2.0），由用户决定
- 若邮箱/家 < 1.0：主动建议检查锚点纯度（L-46），不硬解释为正常
- "未知的也要"：默认已包含（contactVerifyStatus=["valid","unkown"]），无需用户要求
- **保存期间每 5–10 秒播报一行**：运行 `tools/save_company_cli.py status --plan <计划路径> --watch`，AI 须把工具的 stderr 进度转播给用户；工具不会保证 GUI 自动推送（未实测）。只显示可信的已处理公司数，数字未知就说未知；不编造扣点或余额。平台完成仅代表任务结束，须先对账再发本卡；轮询失败或达到上限须说明未完成。保持原有三行进度和唯一回复点。
