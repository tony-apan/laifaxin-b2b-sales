# S0 产品画像方案（方向参考，不让用户选买家类型）

```text
【这段不用回】先说下我打算怎么找：优先往「离您产品最近、一次买得多、愿意回邮件问价」的方向找。不在这儿给您列具体买家类型——列出来也是我猜的，**仅供参考**，最后以平台返回的名单为准。

💡 手头要是有网址，随时发我，两类用处不一样：
- 🌐 **您自己的官网、产品页**：我用来**提炼您自家的产品和公司卖点**，写开发信时用；
- 🎯 **您认得的客户官网**（老客户、有人回您问过价的买家、看中的同行买家）：我看**对方到底在买什么**，再拿它当**样板客户**去找更多同类的。

说完这些之后的流程：①连接来发信账号（开工第一步已连好——复用已验证会话或专用浏览器自动连接，这里不再重复操作）
②我向您要产品/公司资料（这次只问产品；公司资料可选，想补再发我；建立本地资料，可跳过、不逼问）
③联网后平台帮您猜几类可能买您货的买家，请您挑（那是更细的名单，不是重复问一遍）④抽查名单质量——
每一步我都会先说清要做什么、大约多久、要不要您动手。
```

## AI 执行要点与边界

- **★不产出买家类型**：本卡只给"往哪个方向找"的参考（离产品近/买得多/会回邮件），**不得**列出 A/B/C/D 买家类型、角色、名单、字母选项，也不得要求用户选字母或把它映射成标签。
- **★平台没返回时不兜底**：不得用本卡的"方向参考"冒充买家类型清单；S2 失败就停在可重试状态，话术照 `S2-segment-confirm.md`「这次没推出来」块。
- **适配结论已前移**：强/条件/弱适配由 `S0-fit-notes.md` 在用途卡之前独立说明，本卡不重复判断。
- **两类网址（D1-D4）**：用户自己的网址 → 只走 `specs/website-profile-sop.md` 六区候选、批准后入档；买家网址 → 只作 S3 起点；第三方参考页 → 只作分析；归属不明 → 先问一句"这个网址是您自己的，还是一个您认得的买家的？"。
- 公司级资料与产品级资料分开回落；邮件签名始终只有纯个人昵称；客户/联系人第三方联系方式不索要。
- 昵称必须过 `tools/profile_utils.py` 的 `validate_nickname`；不合规请用户改，AI 不得代填或截断。
