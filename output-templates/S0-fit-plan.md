# S0 产品画像方案（方向参考，不让用户选买家类型）

```text
【找客户规划 · 不用回】
找客户优先往离产品近、买得多、愿回邮件的方向。
手头若有网址随时发我：
- 🌐 自己的官网：提炼产品/公司卖点
- 🎯 认得的客户官网：当样板客户找同类
之后的流程：连接来发信账号（已连好）→ 产品/公司资料（不追问网址）
→ 平台帮您猜买家类型 → 选样板时询问客户官网 → 抽查名单质量。
每步我都会说清要做什么，您点头才做。
该回什么：不用回复，我马上继续。
```

## AI 执行要点与边界

- **★不产出买家类型**：本卡只给"往哪个方向找"的参考（离产品近/买得多/会回邮件），**不得**列出 A/B/C/D 买家类型、角色、名单、字母选项，也不得要求用户选字母或把它映射成标签。
- **★平台没返回时不兜底**：不得用本卡的"方向参考"冒充买家类型清单；S2 失败就停在可重试状态，话术照 `S2-segment-confirm.md`「这次没推出来」块。
- **适配结论已前移**：强/条件/弱适配由 `S0-fit-notes.md` 在用途卡之前独立说明，本卡不重复判断。
- **两类网址（D1-D4）**：用户自己的网址 → 只走 `specs/website-profile-sop.md` 六区候选、批准后入档；买家网址（档案屏不追问，统一在 S3 选样板屏明确询问）→ 只作 S3 起点；第三方参考页 → 只作分析；归属不明 → 先问一句"这个网址是您自己的，还是一个您认得的买家的？"。
- 公司级资料与产品级资料分开回落；邮件签名始终只有纯个人昵称；客户/联系人第三方联系方式不索要。
- 昵称必须过 `tools/profile_utils.py` 的 `validate_nickname`；不合规请用户改，AI 不得代填或截断。
