# S4 审计进行中（过程话术）
```
进度：第 2 步 / 共 6 步
现在：正在抽查名单 · <客群名>（第 <i>/<K> 批）
该回什么：不用回，等我跑完

⏳ 已在您选的样板「<样板域名>」的同类买家里逐页看。这是最花时间的环节，请稍等。

- 方法：在平台搜出的公司名单里逐页看公司资料，判断是不是目标买家；不打开对方网站，也不碰您的账号设置
- 怎么看：一页里像买家的够多就继续往后翻，不够就回到前一页。这个只说明名单像不像，跟有没有人回您、能不能成交无关
- 完成后我会给出：建议保存哪些公司 + 抽查明细

📊 已看 **<X> 页名单 / 预计 <Y> 页**

🎯 该回什么：**不用回**，**您不用做任何事**，等我跑完（预计 **<N> 分钟**）。我会每 10–30 秒报一次进度；如果卡住超时，我先停下告诉您，不会闷着。出结果后给您保存方案，**您点头才会开始存**。
```
## AI 执行要点与边界
- 100页跳→前后3页→连续3页（每页≥50%）滑动窗口→跌破往前；临界=首个<70%窗口的前一窗口末页（细则=threshold-probe-spec v3.1）；判定=AI 语义反思"会不会买"，不是关键词匹配
- **★审计只读中文描述（2026-10-25 收口）**：`audit_company.py` 已强制语义模式，`--match-words/--mode` 不再参与判定；AI 必须先读每条的“中文描述”，直接判断是不是本产品潜在买家。缺中文的条目明确标记“无法据此判断”，不得拿英文摘要顶替。
- **★按客群客户线审计（铁律 7d）**：标题写「<客群名>（第 i/K 批）」；匹配率以**本客群客户线**为分子（threshold-method §一 计数规则）——如批发商档只把直采线渠道商计入该池，OEM/拓品线索单列计数、不进本池保存范围（同节 边界裁决）。多客群分批时每批独立审计，禁止跨客群混算
- 每页判定表留痕（公司/角色/客户线/理由）；边界案例做敏感性检查
- 正式推进 S4 必须生成 `evidence_mode:"live"` 的 audit-manifest，并绑定真实线上审计/独立review文件hash；模拟、离线、网络桩、占位只能输出演练报告，禁止据此保存或推进状态
- 未完成不能保存；结果是名单筛选阈值，非客户质量保证
- **★总时长不许空口编**：还没跑完第一批时，不要说「总共约 N 分钟」这种没有依据的承诺；改为「我先跑第一批，约 1–2 分钟出第一批结果，再按实际速度告诉您大概还要多久」。有了第一批实测速度后，再给区间（如「按这个速度，全部约 8–12 分钟」），并每 10–30 秒继续播报。
