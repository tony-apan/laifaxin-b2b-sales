# S2 具体客群确认（推演结果展示）

> **与 S0 的区别**：S0 是您选的**获客方向**（一组，决定往哪推）；这里平台推演出的**具体客群**（单个，决定实际打谁）——是上一步的细化，不是重来一遍。
```
【具体客群推演完成】基于您在第一步选的获客方向 <方向字母>，平台为「<产品>」推演出 <N> 个具体买家客群（已剔除疑似历史残留簇）。

💡 **一句话结论**：我最推荐第 <X> 个「<客群名>」——<一句话理由，如"这批人会成批采购、回复也快">。
下面的表是完整对比；**您不用全看懂，只看最后一列「我的建议」也能选**。

| # | 这类买家 | 会买吗 | 多久成交 | 回复快慢 | 这类买家多吗 | 找得到邮箱吗 | 同行多吗 | 我的建议 |
|---|---------|--------|---------|---------|-----------|-----------|--------|---------|

| ... | | | | | | | | |

📖 表头人话解释（对上表列）：
- **会买吗**＝这类买家会不会真的采购您的产品（不是来找资料凑热闹的）
- **多久成交**＝从发出邮件到对方回话问价的大致节奏；**回复快慢**＝回信及不及时
- **同类买家多吗**＝这个方向能挖出多少家公司；**找得到邮箱吗**＝能不能拿到联系方式
- **同行多吗**＝这块市场挤不挤（越少越容易出头）

⚠️ 如果某些客群和您之前跑过的产品方向撞车，我已经标出来并默认帮您剔除了。

⚠️ 周期长的客群（回复以季度~年计）：属正常，但结果预期要放长——我会如实标注，并建议减少轮次或改人工慢慢培育（第一步已经判断过您的产品适配度）。

**现在轮到您**：回复编号（如"1,3"）或"全要"；只看懂一个也够，回那个编号就行。也可以说要改哪里。
```

**★选中 ≥2 个客群时的必加提示（不硬拦，但必须说清）：**

```
您选了 <K> 个客群（<客群1>、<客群2>、…）。

这几个客群的采购需求和话术不一样，建议**分开做**：
每个客群单独建标签、单独写开发信、单独建跟进计划——先做完一个看效果，再做下一个。
混在一起做，它们会共用一个标签和一套话术，效果会打折。

成本您也了解一下：<K> 个客群 = <K>×48 = <K*48> 封开发信（每批 12 轮 × 4 变体）+ <K> 条跟进计划（每个客群一套）。

请选：
A. 先做 1 个（推荐）：告诉我先做哪个编号，做完这个再回来做下一个
B. 都做：我按顺序分成 <K> 批，一批做完再做下一批
```

## AI 执行要点与边界
- 六维列必填（精准买家/成交周期/询盘速度/量级/邮箱可得/竞争度）+ ⭐推荐列
- 只打印不代选；禁止顺带索要公司/官网/邮箱等
- 与历史产品客群重叠的簇默认剔除并说明
- **★措辞区分（防"重复做了两遍"误解）**：本节点叫「具体客群」，S0 叫「获客方向」；展示时必须写"基于您选的获客方向 <字母>"，让用户看出这是细化而不是重来
- **★多客群必须提示分开做**（铁律 7d）：选中 ≥2 个时**必须**展示上面的提示块，给出"先做 1 个 / 都做（分 K 批）"选项，并如实告知模板与序列数量翻倍（K×48 模板 + K 条序列，48=12轮×4变体）。不硬拦用户选多个，但不得让用户以为可以合并执行
- **★落档（工具化）**：用户选定后用 `python3 tools/segment_select.py --record <record> --segments "S04:客群名,S05:客群名"` 写入 `operation-record.md` 的「客群」行；再在 `segments/<ID>-<客群名>.md` 为每个客群建档（含 标签/保存/序列 三列）。禁止只在对话里记、不落档
- **★落档校验**：`segment_select.py` 只允许 S1/S2/S3 状态落档（已进保存阶段拒绝改客群）；`--dry-run` 可预览
- **★执行顺序**：多客群按用户确认的顺序分批——一个客群走完 S3→S4→S5→S7→S8→S9→S10 再做下一个；不得并行铺开或合并写操作
- **用户可见文案纪律**：不出现 `segment_name`/`value_path`/`inference-*` 等内部术语
