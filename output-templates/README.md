## 全局规则（每个模板都隐含，违反即错）

0. **★菜单/选项：逐行 + emoji + 标 ⭐推荐 + 上限 4 项（2026-09-10 用户拍板）**：任何给用户选的任务菜单/选项列表，**逐项独立成行**、每项前加 emoji、明确标注推荐项，且**项数上限 4 并按状态裁剪**（只放当前状态可用的动作）。**禁止**把编号压成 `①②③` 连成一行（用户反馈"1234 不明显"）；**禁止**列出不适用项（如新用户看到"继续项目（无）" → 选择困难）。聊天话术鼓励 emoji；**邮件正文**另有禁 emoji 规则（`specs/sequence-config.md`），两处不混用。

1. **渐进索取**：每步只问当前必需的一件事；开局只问纯个人昵称+一句话产品（目标市场可选），不要催 token；完成产品了解/适配、首次平台调用前再一键双取 token+当前工作空间 orgId。
2. **主动索取并分层回落**：公司名/官网/联系邮箱/默认市场→`.local/operators/<operator_key>.md`；产品线/卖点/认证/产能/MOQ/交期/价格带→当前 product-profile。每次单独问一组、给填空模板、可跳过不逼问。邮件末尾签名区只有昵称；confirmed 且有字段级来源的产品事实可进正文卖点；潜在买家/联系人第三方资料不索要。
3. **真实能力**：系统不自动识别回复/不自动打标签；人/AI助手打"询盘"标签且实际生效后才停邮件。
4. **确认不豁免**：用户说"自由发挥"只能跳过展示，写操作确认与审批不能跳。
5. **断言分级**：实测✅/引用📚/推断⚠️/假设❓——不把假设说成事实。
6. **邮件正文英文、内部命名中文、标签=客户群体名（非产品名）**。
7. **适配预期管理**：S0 先按 specs/product-fit.md 判强/条件/弱适配并展示结论；客群成交/询盘周期以季~年计时（条件/弱适配），如实说明 12 步节奏按快周期品类设计、建议调低轮次或转人工培育。
