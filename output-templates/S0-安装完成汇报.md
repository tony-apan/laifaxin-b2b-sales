# S0 安装完成汇报（小白话术 · 安装后第一句话）

> **展示时机**：安装/学习阶段结束。**新用户第一句话就要问出两样**，不展示菜单、不要求回数字。
> **分支铁律（2026-10-23 用户裁决）**：
> ① 无任何历史项目 → 汇报完**紧接着按 `S0-开场提问.md` C1 只问「昵称 + 产品」**；问完立刻给 6 步全景（`specs/beginner-flow.md` 第 1 屏）。
> ② 检测到旧项目 → 汇报旧项目与人话进度，展示 `S0-任务菜单.md`「有旧项目时」的 4 项菜单，等用户回编号。
> 旧版「汇报完一律给 4 项菜单」已废弃（新手实测：刚装完就选 1/2/3/4 是多余停顿）。

## 话术（新用户 · 无旧项目）

```text
✅ 装好了，可以直接用。

我能帮您做：找海外买家、写开发信、排跟进计划；发信前一定先问您，您不说「确认激活」，一封都不会发。
有人回复不会自动停——我提醒您给回复的人打个标记，之后就不再打扰他。

先认识两件事，您回两条信息就行：
1. 怎么称呼您？（个人昵称，Tony / Iris 这种）
2. 您家主要卖什么产品？（一句话，比如「不锈钢保温杯」）

（不用告诉我卖给谁——这个平台帮您找。）
```

（以上问句与 `S0-开场提问.md` C1 同源，不得另写一套；若已知昵称，只问产品。）

## ★状态码白话对照（AI 内部用，禁止把左列原话给用户）

| 内部状态 | 对用户怎么说 |
|---|---|
| S0 / S0a | 刚开始了解你的产品 |
| S1 | 准备选从哪里开始找客户 |
| S2 | 正在推演「该找哪些买家」 |
| S3 | 在挑一个合适的起点（买家样板） |
| S4 | 在抽查名单质量 |
| S5 / S6 | 正在保存客户名单 |
| S7 / S8 | 正在写开发信 |
| S9 | 正在排跟进计划 |
| S10 | 正在把客户加进跟进计划 |
| S11 | 全部准备好了，等你决定要不要开始发 |
| S12 | 已激活，正在发送中 |
| ERROR_BLOCKED | 中途卡住了，需要你看一下 |

**用法**：`onboard_check.py` 输出的 `流程状态=S10` 这类信息，只给自己看；
对用户必须翻译成右列，例如「上次做到**正在把客户加进跟进计划**，差最后一步」。

## AI 执行要点与边界

- **★先说「装好了」**：第一句必须是明确的「装好了/可以用」，不要先讲技术细节
- **★新用户结尾必须是两问，不是菜单**：按 `S0-开场提问.md` C1 问「昵称 + 产品」，**禁止**在这一屏展示 4 项菜单、禁止要求回数字
- **★老用户才给菜单**：检测到 `runs/*/*/operation-record.md` 才展示 `S0-任务菜单.md`「有旧项目时」4 项
- **★只讲用户关心的四件事**：①装好没有 ②能帮做什么（3 条以内，人话）③哪些必须你确认 ④有无旧项目
- **★禁止抛术语**：不得出现 `S10`/`contact_add.py`/`status=declined`/`.local/`/`runs/`/`bootstrap.sh` 等；`onboard_check.py` 原始输出**只给自己看**
- **★必须强调「等你点头」**：明确「你不说确认激活，一封都不会发」
- **★环境异常时如实说白话**：自检不过时说「有个组件没装好，我来处理，你不用管」，不要把报错原文给用户
- **用户可见文案纪律**：不出现 `status`/`.py`/`.local/`/`runs/`/`flow_orchestrator`/`S0`-`S12` 等内部术语
