# S0 安装完成汇报（小白话术 · 安装后第一句话）

> **展示时机**：安装/学习阶段结束、展示任务菜单**之前**。
> **为什么需要**：README 要求 AI 汇报"安装目录/环境/能做什么/哪些要确认/有无旧项目"，
> 但原来**没有模板**——AI 容易直接把 `onboard_check.py` 的原始输出抛给用户，
> 里面是 `S1`/`S10`/`contact_add.py`/`status=declined` 这类术语，小白完全看不懂。
> **本模板就是给 AI 的"翻译稿"**：把内部状态翻成人话，只讲用户关心的四件事。

## 话术（新用户 · 无旧项目）

```
✅ 装好了，可以直接用。

我检查了运行环境，都正常；也把规则学完了。
简单说，我能帮您做这些：

  🔍 找海外买家——您告诉我卖什么，我批量找、逐个筛，挑出真正可能买的公司
  ✉️ 写开发信——按不同买家写不同角度，批量准备好，不是一封封手写
  📅 排跟进计划——首封之后自动分轮跟进，直到对方回复或明确拒绝
  ⏸️ 但都停在"等您点头"——发信前一定问您，您不说"确认激活"，一封都不会发

有三件事您随时可以喊停：看不清名单可以让我重筛；不喜欢文案可以让我改；
不想跑可以说停。发现有人回复，我提醒您接手跟进。

👉 现在轮到您：看下面几个选项，**回复数字**告诉我想做哪个就行。
```

（紧接着展示 `S0-任务菜单.md` 的四项菜单）

## ★状态码白话对照（AI 内部用，禁止把左列原话给用户）

| 内部状态 | 对用户怎么说 |
|---|---|
| S0 / S0a | 刚开始了解你的产品 |
| S1 | 准备选从哪里开始找客户 |
| S2 | 正在推演"该找哪些买家" |
| S3 | 在挑一个合适的起点（买家样板）|
| S4 | 在抽查名单质量 |
| S5 / S6 | 正在保存客户名单 |
| S7 / S8 | 正在写开发信 |
| S9 | 正在排跟进计划 |
| S10 | 正在把客户加进跟进计划 |
| S11 | 全部准备好了，等你决定要不要开始发 |
| S12 | 已激活，正在发送中 |
| ERROR_BLOCKED | 中途卡住了，需要你看一下 |

**用法**：`onboard_check.py` 输出的 `流程状态=S10` 这类信息，只给自己看；
对用户必须翻译成右列，例如"上次做到**正在把客户加进跟进计划**，差最后一步"。

## AI 执行要点与边界

- **★先说"装好了"**：用户最想知道的第一件事是"成没成"。第一句必须是明确的"装好了/可以用"，不要先讲技术细节
- **★只讲用户关心的四件事**：①装好没有 ②能帮做什么（用人话，3-4 条）③哪些必须你确认 ④有没有旧项目
- **★禁止抛术语**：不得出现 `S10`/`contact_add.py`/`status=declined`/`.local/`/`runs/`/`bootstrap.sh`/`flow_orchestrator` 等；必须按上方对照表翻成人话。`onboard_check.py` 的原始输出**只给自己看**
- **★必须强调"等你点头"**：新用户最大的顾虑是"会不会自动发信/乱花钱"。必须明确"你不说确认激活，一封都不会发"
- **★给"随时可喊停"的承诺**：降低小白的心理门槛——看不清名单可重筛、不喜欢文案可改、不想跑可停
- **项目名用大白话**：`product_key=raft` → 对用户说"皮筏艇找客户"；不得直接抛英文 key
- **★环境异常时如实说白话**：自检不过时说"有个组件没装好，我来处理，你不用管"——**不要把报错原文给用户**，也不要让用户自己去装 Python
- **结尾必须接菜单**：汇报完立刻展示 `S0-任务菜单.md` 的四项菜单，不要停在"我装好了"就等用户说话（小白不知道能问什么）
- **用户可见文案纪律**：不出现 `status`/`.py`/`.local/`/`runs/`/`flow_orchestrator`/`S0`-`S12` 等内部术语
