# S0 产品知识档案确认（AI 提炼 → 用户确认 → 回落）
```
【产品知识档案·待确认】我已根据 <您提供的产品资料 / 您跳过后允许使用的通用口径> 提炼出下面内容。确认后将回落到 `runs/<operator_key>/<product_key>/product-profile.md`（当前 status=<draft/declined>，拟更新为 <confirmed/declined>），之后找客群、审计客户线、写正文卖点和序列钩子都绑定这份档案的版本/hash。

| 字段 | 内容 |
|------|------|
| ① 产品定位 | <一句话：卖给谁/解决什么> |
| ② 产品线 | <品类/子品类/SKU/成分配比> |
| ③ 核心卖点 | <1. … 2. … 3. …（每条一句，≤5条）> |
| ④ 目标客群+市场 | <国家/语言/渠道角色> |
| ⑤ 规格/认证 | <型号/标准号/证书/参数——有来源才写> |
| ⑥ 差异化 | <和竞品比强在哪> |
| ⑦ 合规/禁忌 | <禁运区/受管制品类/环保声明——有依据才写> |
| ⑧ 可引用数字 | <产能/MOQ/交期/价格带——用户给或官网可查才写，没有不编> |

📌 字段级来源：每一项分别标 <用户原话 / 具体 URL / 推断⚠️> + confidence；数字、认证、交期、价格无来源不写。
📌 档案控制：`profile_version=<N>` · `status=<draft/declined>` · 确认后生成 `content_sha256`；以后补资料会升版本并使旧模板计划失效。

请您重点核对 ③卖点、⑤认证和⑧数字及来源。要改的直接说；没问题回复“确认”，我用 `product_profile.py confirm` 回落存档。
```

## AI 执行要点与边界
- ①S0a 单独主动索取（不和 ABCD 选择挤同一轮）→ ②有资料则读官网/目录并逐字段标 source/confidence；没资料/用户跳过也 init --declined 建档 → ③按模板展示给用户 → ④确认后用 `product_profile.py confirm` 回落 `runs/<operator_key>/<product_key>/product-profile.md`
- 公司名/官网/联系邮箱属于公司级资料，回落 `.local/operators/<operator_key>.md`（见 operator-profile-sop）；认证/产能/MOQ/交期/价格带属于当前产品档案
- 邮件末尾签名区只有昵称；confirmed 且有来源的产品事实可用于正文卖点；客户/联系人第三方资料禁止写入本档案
- 来源必须标注：用户给的/官网解析的/行业推断⚠️——**数字与认证无来源一律不写**
- 档案与用户一句话产品/目标市场冲突 → 以用户口径为准并标注差异
- 回落成功后，后续 S2 客群/S4 客户线/S7 卖点/S9 钩子全部从该档案取知识
