# S0 产品知识档案确认（AI 提炼 → 用户确认 → 回落）
```
【产品知识档案】我读了您给的 <官网/产品目录链接>，提炼出这份档案存到 runs/<您的昵称>/<产品>/product-profile.md，之后找客群、写开发信、建序列都从它取。

| 字段 | 内容 |
|------|------|
| ① 产品定位 | <一句话：卖给谁/解决什么> |
| ② 产品线 | <品类/子品类/SKU/成分配比> |
| ③ 核心卖点 | <1. … 2. … 3. …（每条一句，≤5条）> |
| ④ 目标客群+市场 | <国家/语言/渠道角色> |
| ⑤ 规格/认证 | <型号/标准号/证书/参数——有来源才写> |
| ⑥ 差异化 | <和竞品比强在哪> |
| ⑦ 合规/禁忌 | <禁运区/受管制品类/环保声明——有依据才写> |
| ⑧ 可引用数字 | <产能/MOQ/交期/价格带——用户给或官网可查才写，没有不编> |

📌 来源说明：<来自您提供的官网> <来自目录解析> <行业合理推断⚠️ 请核对>。

请您核对，尤其是 ③ 卖点 和 ⑧ 数字（这两处最影响开发信真实性）。要改的直接说，我改完再回落；
没问题就回"确认"，我马上回落存档，继续按客群方向推进。
```

## AI 执行要点与边界
- ①先读用户给的官网/目录/卖点 → ②按 RULES「产品知识档案」8 字段提炼 → ③展示给用户确认（③卖点/⑧数字是核对重点）→ ④确认后回落 `runs/<运营方>/<产品>/product-profile.md`（随档案层）
- 有产品资料（官网/目录/卖点）→ 读取提炼；没有 → **AI 主动要**一次（给填空模板+示例、可跳过、不逼问）→ 拿到或跳过后按行业通用口径出档案；不要为"没资料"就跳过建档案
- 公司名/官网/邮箱/认证/产能/MOQ（用户自己的商业资产）可主动要，但**写进正文/落款须在 S7 展示带/不带效果，由用户拍板**；客户/联系人邮箱等他人信息永不索要
- 来源必须标注：用户给的/官网解析的/行业推断⚠️——**数字与认证无来源一律不写**
- 档案与用户一句话产品/目标市场冲突 → 以用户口径为准并标注差异
- 回落成功后，后续 S2 客群/S4 客户线/S7 卖点/S9 钩子全部从该档案取知识
