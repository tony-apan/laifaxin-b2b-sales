# S0 产品知识档案确认（AI 提炼 → 用户确认 → 回落）
```
【产品知识档案 · 待您确认】我根据 <您提供的产品资料 / 您跳过后允许使用的通用口径> 整理出下面这份档案。它存在您本机、不会上传；后面找客户、写开发信都以它为准。

💡 **一句话总结**：8 项我都填好了，**其中 3 项请您重点看一眼**；剩下 5 项是常规内容，没意见可以跳过不看。

| 字段 | 内容 |
|------|------|
| ① 产品定位 | <一句话：卖给谁/解决什么> |
| ② 产品线 | <品类/子品类/SKU/成分配比> |
| ③ 核心卖点 | <1. … 2. … 3. …（每条一句，≤5条）> |
| ④ 目标客群+市场 | <国家/语言/渠道角色> |
| ⑤ 规格/认证 | <型号/标准号/证书/参数——有来源才写> |
| ⑥ 差异化 | <和竞品比强在哪> |
| ⑦ 合规/禁忌 | <禁运区/受管制品类/环保声明——有依据才写> |
| ⑧ 可引用数字 | <产能/MOQ/交期/价格带——用户给或官网可查才写，没有不编> |

📌 每项后面都标了来源：<您说的 / 官网原文 / 我的推断⚠️>。认证、产能、起订量、交期、价格这些，没有可靠来源我不会写进档案。
📌 以后您补充资料，我会更新这份档案；之前基于旧版做的开发信会提示您重新确认。

请您重点核对这三项：**③核心卖点**、**⑤规格认证**、**⑧可引用数字**（对上表编号）。

**要改的地方直接说；没问题回「确认」。**

👉 顺便说一件事：如果您手上有**询盘客户、或您认得的精准买家官网**，现在就可以发我——它是最好的起点，能直接跳过推演、更快找到同类客户。没有也没关系，回「确认」我就带您推演客群。
```

## AI 执行要点与边界
- ①S0a 单独邀请补充资料（不和 ABCD 选择挤同一轮）→ ②用户给自己的网址时先走独立 `website-profile-sop.md`，生成六区候选并按 `S0a-网站资料确认.md` 展示，批准后才导入；用户给文字/文件则按用户来源提炼；没资料/跳过也可 init --declined → ③按模板展示正式档案 → ④确认后用 `product_profile.py confirm` 回落
- 公司名/官网/联系邮箱属于公司级资料，回落 `.local/operators/<operator_key>.md`（见 operator-profile-sop）；认证/产能/MOQ/交期/价格带属于当前产品档案
- 邮件末尾签名区只有昵称；confirmed 且有来源的产品事实可用于正文卖点；客户/联系人第三方资料禁止写入本档案
- 来源值域必须是：`用户` / `URL:https://...` / `推断` / `none`。网站硬事实必须有具体 URL 和原文；数字与认证无来源一律不导入正式档案
- 档案与用户一句话产品/目标市场冲突 → 以用户口径为准并标注差异
- 部分字段填入后，直接用 `product_profile.py confirm` 做写入前结构/来源校验并重算 `sources_status/sources_present`，再运行 `validate --require-confirmed` 终检；不要在 partial draft 时先单独 validate，把预期的来源状态未重算误报成档案失败
- 回落成功后，后续 S2 客群/S4 客户线/S7 卖点/S9 钩子全部从该档案取知识
- **用户可见文案纪律**：代码块内（用户看到的部分）不出现 `runs/`/`status=`/`sha256`/`profile_version`/`content_sha256`/`draft`/`confirmed`/`declined` 等内部术语——这些只在"AI 执行要点"里给 AI 看
- **起点引导是必给项**：用户确认档案后，若还没给过起点网址，必须用代码块末尾"👉 顺便说一件事"提示一次（不追问、不阻断）；用户给了网址就走快速路径，没给就走推演路径
- **确认后下一步固定是连接平台**（`T-token引导.md`），不得跳过连接直接推演客群
