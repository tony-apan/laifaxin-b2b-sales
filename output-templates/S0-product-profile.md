# S0 产品知识档案确认（AI 提炼 → 用户确认 → 回落）
```text
进度：第 1 步 / 共 6 步
现在：产品资料整理好了，请您核对
该回什么：回 1 认可当前产品资料；回 2 修改

【产品资料 · 待您确认】
💡 8 项资料按现有信息整理，供找客户与写信（无来源标暂无）：

| 项 | 内容 | 来源 |
|---|---|---|
| ① 卖给谁 | <一句话定位：如"海外户外装备批发商"> | <来源> |
| ② 产品线 | <品类：如"不锈钢保温杯、运动水壶"> | <来源> |
| ③ 核心卖点 | <2-3 个卖点：如"自营工厂、交期 25 天"> | <来源> |
| ④ 目标买家与市场 | <买家类型与地区：如"北美户外用品买家"> | <来源> |
| ⑤ 规格和认证 | <标准认证：如"FDA、LFGB"；无标暂无> | <来源> |
| ⑥ 与同行差异 | <优势差异：如"支持小批量定制、免费打样"> | <来源> |
| ⑦ 合规与资质 | <进出口资质；无依据标"暂无"> | <来源> |
| ⑧ 能引用的数字 | <产能、起订量；没有不编标"暂无"> | <来源> |

重点看 ③卖点 ⑤认证 ⑧数字，写进开发信不能编。
- **回 1**：认可当前产品资料，继续下一步
- **回 2**：修改；您可以直接说要改哪项
```

## AI 执行要点与边界
- ①S0a 公司资料按需：首次安装不主动弹（避免多占一轮回复）；用户主动提供公司资料/官网，或换产品/换机复用时才邀请，可跳过 → ②用户给自己的网址时先走独立 `website-profile-sop.md`，生成六区候选并按 `S0a-website-profile.md` 展示，批准后才导入；用户给文字/文件则按用户来源提炼；没资料/跳过也可 init --declined → ③按模板展示正式档案 → ④确认后用 `product_profile.py confirm` 回落
- 公司名/官网/联系邮箱属于公司级资料，回落 `.local/operators/<operator_key>.md`（见 operator-profile-sop）；认证/产能/MOQ/交期/价格带属于当前产品档案
- 邮件末尾签名区只有昵称；confirmed 且有来源的产品事实可用于正文卖点；客户/联系人第三方资料禁止写入本档案
- 来源值域必须是：`用户` / `URL:https://...` / `推断` / `none`。网站硬事实必须有具体 URL 和原文；数字与认证无来源一律不导入正式档案
- 档案与用户一句话产品/目标市场冲突 → 以用户口径为准并标注差异
- **用户发产品照片/链接代替文字时**：先复述「我看这是 <产品>，对吗？」请用户确认；确认后按该来源提炼，不要求用户改发文字；照片里看不清的认证/参数标「暂无」，不猜。
- 部分字段填入后，直接用 `product_profile.py confirm` 做写入前结构/来源校验并重算 `sources_status/sources_present`，再运行 `validate --require-confirmed` 终检；不要在 partial draft 时先单独 validate，把预期的来源状态未重算误报成档案失败
- 回落成功后，后续 S2 客群/S4 客户线/S7 卖点/S9 钩子全部从该档案取知识
- **用户可见文案纪律**：代码块内（用户看到的部分）不出现 `runs/`/`status=`/`sha256`/`profile_version`/`content_sha256`/`draft`/`confirmed`/`declined` 等内部术语——这些只在"AI 执行要点"里给 AI 看
- **目标客户网址统一延后至 S3 明确询问**：档案屏仅核对 8 项产品资料，不追问、不询问目标客户网址；在 S3 选样板客户屏明确询问「有没有目标客户（客户、非自己官网）网址」，有则定位并分析样板客户，没有/跳过则平台推演候选；已给过网址不再重问
- **连接已在档案之前完成**（安装自检通过后第一业务动作，见 `T-token-guide.md`）；档案确认后不得再让用户连平台，也不得跳过客群建议直接保存
