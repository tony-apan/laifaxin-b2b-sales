# 11 · 从头演练脚本

> 用法：新 AI 接手时**按本文顺序执行**，每节先 `node_gate.py <节点>` 拿模板与必填字段，再输出话术。
> 本文所有数字均来自 2026-10-21 真实运行（Tony / 金属粉末 / 3D 打印金属件），不是估算。

## 〇、全局参数速查（唯一真源：CORE-POINTS.md）

| 项 | 值 | 说明 |
|---|---|---|
| 精准度阈值 | **≥70%** | 单页命中率，不设材料附加条件 |
| 临界判定 | **连续 3 页（每页≥50%）均值 <70%** | 单页跌破只记抖点，不立刻停 |
| 翻页步长 | 1 / 50 / 100 / 150 … | 粗扫到跌破，再在跌破页与上一页之间二分细化 |
| 页大小 | **pageSize=10** | 审计与保存必须同 pageSize、同 filters、同排序 |
| 默认排除 | **CN / TW / HK / MO** | 可一句话关掉 |
| 每家邮箱上限 | contactMaxCount=3（可 2） | 实测均值 **1.53 个/家** |
| 扣点实测 | **1.81 点/邮箱** | 17,176 点 ÷ 9,510 邮箱 |
| 预算公式 | S=点数×50%；E=S÷1.8；N=E÷1.5 | 反推：K 邮箱→家数 K÷1.5，预算 K×1.8 |
| 单次保存上限 | **2 万点**（≈1.1 万邮箱≈7,400 家） | 超限必须先报账征询 |
| 标签命名 | **语言-产品-角色** | 例：`英语-金属粉末-3D打印服务商` |
| 首轮目标 | 低于 3000 邮箱不算数，最好 >1 万 | 达不到如实报差多少 |

## S4 · 边界审计（找 70% 临界点，不能只抽几页）

**动作**：以 `protoshape.ch` 为关键词搜主库，**pageSize=10、排除 4 区**，按 1/50/100… 跳页看命中率，直到连续 3 页（每页≥50%）均值 <70%，再二分细化。

**AI 说**（S4-audit-running.md）
> 开始抽查（后台跑，您不用管）。规则：**≥70% 就算过关**，看到跌破还要再确认几页，不能只看一页就停。

**实测数据（2026-10-21，pageSize=10，排除 4 区）**

| 页 | 命中率 | | 页 | 命中率 |
|---|---|---|---|---|
| 1 | 90% | | 400 | 80% |
| 50 | 90% | | 500 | 80% |
| 100 | 100% | | 600 | 90% |
| 150 | 100% | | 620 | 80% |
| 200 | 90% | | 622 | 60% ⚠️ |
| 250 | 70% | | 623 | 90% |
| 300 | 80% | | 625 | **60%** |
| 680 | 20% | | 630 | **50%** |
| 700 | 30% | | 660 | 30% |
| 900 | 0% | | 1000 | 0% |

**判定逻辑（写死）**
1. 粗扫：1 → 50 → 100 … 每次 ×1.5~2，直到出现 <70%
2. 发现跌破：在"最后达标页"与"首个跌破页"之间二分（如 620 达标、625 跌破 → 试 622/623）
3. 结论：**临界带 ≈ 620~624 页**（6,200~6,240 家）
4. 单页抖点不算跌破；**连续 3 页（每页≥50%）均值 <70%** 才判跌破
5. 全程与保存用**同 pageSize、同 filters、同排序**，否则不可比

**异常分支**
- 前 10 页就 <70% → 换种子（回 S3），不要硬存
- 搜不到 70% → 如实报"这个锚点覆盖不足"，给替代锚点

**用户回复**：不用回（可打断）。

## 附：异常与红线（AI 必背）

1. **不许自己编关键词** → 只用平台 `query_en`
2. **不许把"我建议"当"用户同意"** → 每个写操作单独拿指令
3. **不许在汇报里漏标签/数量/均量** → 缺一项算违规
4. **不许把"上限"当"实得"** → 3 个/家是上限，实得 1.53
5. **不许点数为 1:1** → 实测 1.81 点/邮箱
6. **不许单次超 2 万点不问**
7. **回「不要保存」类否定句一律当拒绝**（含后置否定）
8. **老脚本一律不用** → 只走 `save_guard` / `authorize_write`
