# 设计：如何确保 AI 读了规则再干（而不是不看直接干）

> **状态（2026-10-21）**：M1–M4 是早期 GATE/自检设计，已被审查否定，仅作历史存档；当前方案是“动作前准备展示原文/字段/推导 + 执行时重验依赖”，见下方修正节及 RULES/SKILL。不得把 GATE 或 hash 宣传成“读懂/真人授权/不可伪造”的证明。

## 问题本质

用户问：「如何确保 AI 读了再去干，而不是现在看都不看直接干？」

实证：CORE-POINTS.md:8 白纸黑字写「禁止自编关键词」，我读过，实操时仍自编。
→ **说明"要求读"无效，必须让"没读"在技术上做不了事。**

三个结构性原因：
1. 规则是散文 → 读完不遵守也没后果
2. 读没读不可检测 → AI 无法证明，用户无法验证
3. 规则不在动作路径上 → 规则在 .md，动作在 API，两者无绑定

## 四个机制

### M1 读规则生成通行证（GATE）（历史提案，已否决）

```
# （已否决、从未实现：该"规则闸"脚本不存在，不要照着跑）
  → 校验：RULES-CARD.md + CORE-POINTS.md 的 sha256
  → 输出 GATE=<sha12>，含 {files, hashes, ts}
  → 有效期 5 分钟（与 render_guard 一致）
```

- 搜索/保存/建序列等**写动作必须带 GATE**
- GATE 过期 → 拒绝
- 规则文件 hash 变了（规则更新）→ 旧 GATE 失效，强制重读

**产品要求：先能出示凭证，而不只是声称自己读过。**

> **否决理由（2026-10-21）**：GATE 只证明“某工具在某时对文件算过 hash”，不能证明模型读过/理解/遵守；可伪造、可重放，不能当读规则或真人授权证明。保留此节仅作历史，不实现、不宣传。

### M2 规则压缩成 10 行卡

630 行（CORE 154 + SKILL 223 + RULES 253）没人真读。
抽出「违反就花钱/花钱或损失信誉」的 10 条 → `RULES-CARD.md`。

候选 10 条：
1. 搜索词 = 平台 query_en 原文（附 product_id + segment_name 来源）
2. 连续5页窗口 ≥70% 可按确认计划保存；不擅自缩量，20家若用户明确且计划成立可存
3. AI 不得自行缩量/扩量；用户明确小规模或弱适配建议须进入同一 plan 确认
4. 单次建议上限 2 万点（默认建议，带 source_ref/version；不是硬规则）
5. 保存 / 建计划 / 实际发送 三件事必须分开确认
6. 用户回数字 = 选序号，不是扩量授权
7. 用户可见话术：禁术语/行话/抽象词（有黑名单）
8. 人民币只在当前价源明确时估算；旧 0.03 元/点不作硬口径
9. 三席回执 + 全量测试绿 才准提交
10. 任何"用户要做什么"的文案必须对照实现验证

### M3 动作前自检（失败即拒绝，不是提示）

| 动作 | 检查项 | 不通过时 |
|---|---|---|
| 搜索 | S3 是否有当前轮 query_en 逐字来源；S4 是否有已选域名/选择记录 | 拒绝；旧轮/跨产品/自编词在 HTTP 前拒 |
| 保存 | N/E/P/B/max_points 有来源，P≤min(B,max_points)，N 与 confirmed plan 一致 | 拒绝或要求新 plan；不自行缩量 |
| 保存 | 单次建议上限 2 万点（带来源/版本，不是硬上限） | 超出走新 plan 报账并确认 |
| 保存 | 是否 4 区默认排除 | 拒绝 |
| commit | 三席回执 + 全量测试绿 | 拒绝 |

### M4 动作留痕可追溯

每个写动作落盘一条：
```json
{"action":"search","gate":"<sha12>","rule_ref":"CARD#1","params":{"keyword":"<query_en原文>","source_segment":"..."},"ts":...}
```
事后扫：动作没有对应 rule_ref → 违规。

## 【审查后重大修正｜2026-10-21】原设计方向错误，改为"动作约束门"

### 被审查否定的核心假设

原设计（M1 GATE）假设：给 AI 发一张"已读规则"的凭证，就能保证它读过。

审查结论（luna，两轮一致）：
> **GATE 只证明"某工具在某时对文件算过 hash"，无法证明模型读/理解/遵守；不能叫读规则证明。**

因此 docs/13 早期版本（M1~M4）**不作为落地方案**。保留仅作历史。

### 修正后的方向：验证动作，不验证"读过"

```
✗ 你读过 query_en 规则吗？→ 出示 GATE（可伪造/可重放/证明不了）
✓ 你这次要搜的 keyword，是否 == 来源记录的 query_en？→ 不等就拒绝
```

**动作校验比出示 GATE 强，但仍不是“无法伪造”**：它只证明被检查的请求参数/本地记录符合绑定关系，能挡误操作与参数漂移；程序仍可改写本地文件/调用参数，测试中的平台回包也可由桩伪造，不能证明真人授权、模型理解或平台实际执行。不要对外宣称“无法伪造/已读懂”。当前推荐：prepare 展示本次相关规则原文/来源字段/推导，execute 重验同一来源/计划/审计范围/预算/标签依赖，失败在 HTTP 前拒绝。搜索链固定为 S3 query_en 逐字 → candidate id/base-info → S4 已选域名 → S5 同一审计范围，禁 similar-list。

### 实现层级（按强度，从强到弱）

| 层级 | 强度 | 落地方式 |
|---|---|---|
| ① 动作工具入口 | **最强** | 搜索 wrapper 校验 keyword==query_en；保存入口校验预算/用户确认/payload 一致；**拒绝路径零网络请求** |
| ② 受保护分支 CI | 强 | 审查回执 + 全量测试 + 绑定 commit SHA，阻断 --no-verify |
| ③ SKILL 状态机 | 中 | 每节点触发回读，但可绕过，不作安全边界 |
| ④ 本机 hook | 弱 | 只做即时反馈 |
| ⑤ AI 自觉/卡片 | 最弱 | 只提醒，不宣称强制 |

### 借鉴 save_guard.py 的现成做法

- 唯一副作用入口
- `authorize_write(action, payload)` 绑定 action + payload_hash
- O_EXCL 原子占位（防并发双花）
- **网络请求放在全部校验之后**（失败前零副作用）
- V2 保存改为 `save_company_cli.py prepare/confirm/execute` 的 confirmed plan + `save_plan/rule_check` 依赖校验；`authorize_write` 仍用于模板/序列/激活，不把保存旧裸 payload 入口留下。

### 必须补的 7 项遗漏（luna 指出候选卡缺失）

1. S4→S5 必须有真实 live 审计 + 独立审查放行（模拟/离线/占位证据不得保存）
2. 工作空间/org 校验与凭据不扩散
3. 用户本轮授权须绑定实际动作+对象+数量+参数
4. S10 加联系人前：保存 finished + 联系人数>0 + 人数对账 + 序列 inactive + 用户确认
5. 参数变更使原确认失效
6. 异常/未验证/模拟状态不得推进到"完成"
7. 只认 `audit_company.py` 的趋势初筛 + 连续5页窗口 + 逐条语义/客户线 + 独立review；High 比例/搜索分数/页1/2/5抽样不是正式精准度

> **证据边界**：探针回调计数只能写“注入回调收到”，不称平台实收/实存；模拟/网络桩不能冒充 live。

### 卡片设计修正：按节点裁剪，不常驻一张

原方案"10 条常驻卡"错误。应改为**按动作触发的规则集**：
- 搜索前 → 只查 query_en 来源绑定
- 保存前 → 只查预算/规模/排除区/用户授权
- 建计划前 → 只查时区/上限/notSentTags
- 提交前 → 只查三席/全量测试
- 只读动作（搜索/适配/复盘）→ **不要求**保存或激活授权

### 允许放行的真实场景（防误拦）

- 用户明确只存 500/20 家 → 按其确认 plan 放行 + 说明影响；AI 不得默认或擅自缩量
- 弱适配 → 诚实解释，由用户选择是否小样；不默认 500，不静默全量
- 余额不足/建议上限 2 万点 → 提出新 N，经用户确认后新 plan；同 scope 不重发，2 万不是硬上限
- S4 单页低于 70% → 按 CORE 连续 5 页滑动平均判，不单点硬拒
- 规则更新中 → 提示重载，不锁死会话；"调用失败"可重试，"写已发生但回执丢失"先查平台状态
