# 02 · 筛选客户（不准客户怎么筛）

> 来源：`https://www.laifa.xin/zhinan/02-filter-customers` + 实测审计方法

## 🎯 核心目标：剔除不准客户，保证发邮件不浪费点数

**无论哪种搜索方式，搜出结果后千万不要直接全选保存！** 先预览并筛选，确保客户精准，才能保证后续发邮件的回复率。

## 一、第一步 · 速览精准度（抽样）

**不要从头一页页看**。正确做法：抽查**前 1~5 页 + 末尾几页**，30 秒判断整批精准度。

| 抽样结果 | 怎么办 |
|---------|--------|
| 前后页 ≥80% 都很准 | ✅ 不用筛，直接保存（保存精准度建议不低于 70%） |
| 前后页 <80% 有杂质 | 👇 进入二、三 精细化筛选 |

> ⚠️ **判断的是"本页"精准度，不是累计平均**。逐页看当前页有多少是目标客户，找到降到 70% 以下的临界页，往前翻。

## 二、第二步 · 选地域范围（排除国家）

**先想清楚：要不要区分国家地区开发？**

### 1. 不分国家（常规打法）
统一用英语开发信，此时**只需排除国内同行**：
- 筛选 → 国家或地区 → **不包含** → 勾选要排除的国家（中国、台湾、香港、澳门等）→ 应用筛选 → **另存为视图并命名**

### 2. 区分国家（精细化打法）
- 筛选 → 国家或地区 → **任意包含** → 勾选目标国家 → 应用筛选 → 另存为视图

**API（实测验证）**：筛选条件格式
```json
{"property":"country_code","operator":"exclude","value":"","values":["CN","TW","HK","MO"],"valueType":"select"}
```
- `operator: "exclude"`（不包含,★实测）/ `"include"`（包含）
- 配合 `logic: "and"/"or"` 多条件组合

## 三、第三步 · 选筛选方式

### 1. 🖐 纯手动筛选（时间多 · 想省点数）
1. 预览结果，明显不匹配的 → 点行尾「拉黑」
2. 提取反复出现的"杂质词"（如"零售商""二手"）
3. 杂质词加入筛选视图的「不包含」条件
4. 保存并预览

> ⚠️ 筛选条件下方选「**满足以上所有条件**」，否则只要满足任一条件就保留，达不到排除效果。

### 2. 🤖 AI 评分（时间少 · 点数充足）
- 先设置**产品档案**（设置-产品档案，填**你的产品**，不是客户的产品）
- 系统结合产品档案判断是否潜在客户，给匹配分（0~100），越高越匹配
- 流程：勾选客户 → 结果列表顶部「AI 评分」→ 填评分规则 → 进批量评分任务查看

**高效用法**：
| 你的情况 | 建议 |
|---------|------|
| 前几页明显精准 | 不用评分，直接抽查后保存 |
| 精准度不确定 | 随机选 30~50 个评分（成本 30~50 点） |
| 大部分匹配 | 放心保存这段 |
| 大部分不匹配 | 换客群/关键词/缩小范围 |

### 3. 🔥 组合打法（折中，老手常用）
前段手动筛 + 后段 AI 评分：先手动筛出并保存最精准的，后段不准的再 AI 评分。

## 四、筛选避坑汇总

| 坑 | 后果 | 怎么避 |
|----|------|--------|
| 一上来全选→AI评分 | 瞬间扣几百到几千点，**不能取消** | 先抽样判断精度，再决定哪段用 AI 评分 |
| **70% 精准就敢全保** | 后续发邮件浪费点数/影响域名信誉 | **保存精准度建议 ≥70%**（★现行默认；教程80%值） |
| 翻页速度过快/频繁点击 | 触发系统限制 | 控制节奏 |

> 💡 补充：AI 评分有 **4 种入口**（AI 数据库批量 / 单家洞察 / 列表悬停 / LinkedIn）+ **6 大评分维度** + **省点数 4 招**，详见官方「AI 评分使用指南」。

## 🔧 实战审计工具（本项目沉淀）

`audit_company.py`：把判定标准写成规则表，逐条输出"判定+命中词+理由"，按页统计精准度，找 70% 临界页。

```bash
# 关键词搜审计（提纯搜）
python3 audit_company.py --query "英文描述句" --pages 1,500,1000 --token $TOKEN --org <orgId> --mode strict --product "猫粮"

# 域名找相似审计
python3 audit_company.py --query "cat food" --pages 1 --domains "<seed-domain>,<seed-domain>" --token $TOKEN --org <orgId> --mode strict --product "猫粮"
```

判定标准（写死在规则表里，不主观漂移）：
- `MATCH` = 会采购本产品（命中匹配词）
- `REJECT` = 无关（命中排除词/杂货一票否决）
- `MARGINAL` = 沾边（宠物行业但非食品/供应商模式）
