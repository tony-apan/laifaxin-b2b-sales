# 📇 产品知识档案（product-profile）

> **作用**：用户给了官网 / 产品目录 / 产品页 / 卖点文字后，AI 读取并**提炼**成这份结构化知识档案，存本目录下。之后 **S2 客群推演 / S4 客户线判定 / S7 开发信卖点 / S9 序列钩子** 全部从这里取知识；零上下文 AI 断点续接也先读它。
> **何时建**：仅当用户**主动给**了产品资料时触发；没给就不建、用行业通用口径，**不主动索要**。
> **冲突规则**：档案与用户一句话产品/目标市场冲突 → 以用户口径为准并标注差异。

## 字段（AI 提炼，非让用户逐一填）

| # | 字段 | 内容 | 来源约定 |
|---|------|------|---------|
| ① | 产品定位 | 一句话：卖给谁 / 解决什么 | 用户/官网 |
| ② | 产品线 | 品类 / 子品类 / SKU / 成分配比 | 官网/目录 |
| ③ | 核心卖点 | ≤5 条，每条一句（为什么买你）| 卖点文字/官网 |
| ④ | 目标客群+市场 | 国家 / 语言 / 渠道角色 | 用户/推断⚠️ |
| ⑤ | 规格/认证 | 型号 / 标准号 / 证书 / 参数 | 有来源才写 |
| ⑥ | 差异化 | 和竞品比强在哪 | 官网/推断⚠️ |
| ⑦ | 合规/禁忌 | 禁运区 / 受管制品类 / 环保声明 | 有依据才写 |
| ⑧ | 可引用数字 | 产能 / MOQ / 交期 / 价格带 | 用户给或官网可查才写，没有不编 |

## 来源标注（必填）

- **来自用户提供**：<哪些项>
- **来自官网/目录解析**：<哪些项>
- **行业合理推断⚠️**：<哪些项，需用户核对>

## 回落与调用

- 回落位置：`runs/<运营方>/<产品>/product-profile.md`（随档案层）
- 确认流程：S0 用过模板展示 8 字段 → 用户重点核对 ③卖点/⑧数字 → 确认后回落
- 调用点：S2 客群（产品线/客群）· S4 客户线（直采/OEM/拓品）· S7 卖点/差异化（可引用数字先给用户看）· S9 钩子（对方视角）
