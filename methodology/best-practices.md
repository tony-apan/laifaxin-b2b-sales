# 最佳实践（Best Practices）

## 🚨 四条铁律（最高优先级 · 防再犯）

> 来源：[lessons/lessons-learned.md](../lessons/lessons-learned.md) 模式总结

1. **先实测再下结论**：任何参数先空 body 试探 → 补全 → 验证结果数字（不是只看 success，要看 data 里的真实数量）
2. **判断标准写死**：可复现，不主观漂移（用规则表/工具，如 audit_company.py）
3. **批量操作先小批量**：先加 1 个看 add 数量（add:8140 ✅ / add:1398445 ❌），确认再全量
4. **接口逆向跟踪懒加载 chunk**：不能只抓主 bundle（sequences 就在 chunk 里）

## 🔍 搜客户

| 做法 | 为什么 |
|------|--------|
| 搜客户的产品词/业务描述词（金主） | 搜服务词只会找到同行 |
| 从精准客户网站提取描述词→AI翻译成英文→再搜 | 提纯词最准 |
| 用多个精准种子域名滚雪球 | 同行精准度天然高 |
| 域名搜索时换行拼多个域名 | 一次找更多相似（实测 lawyerbank 2.4万条） |
| 搜索结果先看邮箱数（emailsCount）再保存 | 优先保存有邮箱的 |

## 🧹 筛客户

| 做法 | 为什么 |
|------|--------|
| 抽样看"本页"精准度，≥70% 才保存（★中等默认，marketing-rules-2.0 §1；旧80%教程值已标注） | 本页判断，不是累计 |
| 排除中国区（CN/TW/HK/MO） | 避免开发国内同行 |
| 先往前翻页找更准的范围 | 尾部数据质量波动大 |
| 手动筛选时提取"杂质词"加不包含 | 一次排除一批杂质 |

## 💾 存客户

| 做法 | 为什么 |
|------|--------|
| 保存就打标签（黄金公式(★已废,RULES铁律7:标签=客户群体中文名非我方产品)） | 后续按标签批量营销 |
| 标签公式：语言-国家-产品-角色 | 语言最前便于按语种筛模板 |
| 邮箱类型选"有效+未知" | 覆盖更多 |
| 每客户保存默认 3 个（存不到数据才按 3→6→9 升阶，每公司邮箱数裁决） | 覆盖决策人+通用邮箱 |
| 慎用高级选项（职位/排除词易致客户流失）；排除4区 CN/TW/HK/MO（铁律0）与"选择前N条"（L-28/29）是例外必用 | 误用易流失客户；该用的不用则混入4区 |
| 分批保存放心 | 系统自动去重不重复扣点 |

## 📧 发信

| 做法 | 为什么 |
|------|--------|
| 群发用优质发送通道 | 多域名/IP切换不怕封号 |
| 发信昵称必设 | 客户看到发件人自然 |
| 发送上限必设（计划24h + 单域名2~10） | 不打扰+不封号 |
| 每轮模板多选随机 | 内容更自然 |
| 后续邮件别只换标题 | 反垃圾系统会识别 |
| 客户回信立刻人工接管 | 1-on-1 提转化 |

## 🤖 AI 开发信

| 做法 | 为什么 |
|------|--------|
| 开启深度思考模式 | 逻辑深度+排版精准度 |
| 一段一句 + ≤100词 + 禁Dear + 零营销感签名 | 扫视友好+规避垃圾邮件过滤器 |
| 钩子用 KEYWORD 高亮（Catalog/Data/Yes） | 极低门槛触发回复 |
| 让 AI 直接生成 HTML 源码 | 导入来发信免二次编辑 |

## 🚨 高频翻车点（避坑）

| 坑 | 后果 | 应对 |
|----|------|------|
| 一上来全选→AI评分 | 瞬间扣几百到几千点，不能取消 | 先抽样 |
| 70% 就敢全保 | 浪费点数/影响域名信誉 | 建议 ≥70%（★2026-08-30 拍板:默认70%执行线,80/60须用户指定） |
| 用服务词搜 | 全是同行 | 用产品词 |
| 翻页过快/频繁点击 | 触发系统限制 | 控制节奏 |
| API 直调保存参数不全（缺 selectKeys/selectOption） | 0 保存 | 纯 API 已破解：`front`+`selectTotal`（L-29）；旧"走界面（Playwright）"结论**已废**（L-35/旧结论清理），勿再用 |
| 忽略发信昵称/发送上限 | 不自然/过度触达 | 高级规则设置 |
