# 📇 产品知识档案 SOP（product-profile）

> **一句话**：把"用户的产品（目录/网站/卖点）"变成一份**结构化、可复用、断点续接可读**的知识档案，随流程走，让 S2 客群更准、S7 卖点更真、S9 钩子更贴合。
> **给谁看**：AI（执行者）。用户版话术在 `output-templates/S0-产品知识档案.md`；本文件是 AI 的"怎么提炼、怎么要、怎么校验"的 SOP。

## 1. 何时触发（两种都触发）

| 用户状态 | AI 动作 |
|---------|--------|
| 给了官网 / 产品目录 / 产品页 / 卖点文字 | 读取 + 提炼（不追问，直接出档案） |
| 只给了"一句话产品"（最常见） | **主动要**一次产品资料（给模板+示例，可跳过，不逼问）→ 拿到或跳过后按行业通用口径出档案（标⚠️） |

> ⚠️ **档案分层**：本 SOP 只管单个产品。跨产品公司资料存 `.local/operators/<operator_key>.md`（旧单文件兼容），按 `operator-profile-sop.md` 主动索取；两类档案都不保存 token 或潜在买家/联系人第三方资料。
> **邮件边界**：邮件末尾签名区只有纯个人昵称；产品档案中经用户确认且有字段级来源的认证/产能/MOQ/交期/价格带可用于正文卖点，推断或无来源的具体事实不得进入正文。

## 2. 主动要的模板（用户没给产品资料时，S0 说一次）

> "为了把客群和开发信写得准，能不能用两三句话告诉我：**① 卖的是什么**（品类 + 给谁用）**② 我的优势/卖点** **③ 主要卖给哪些国家/客群**？
> 不记得也没关系，我可以先按**行业通用口径**给您出一版，您看到不对再改。"

- 只问一次、给默认选项、明确可跳过；用户不给就按行业通用口径（标注推断⚠️），**绝不纠缠**。

## 3. 怎么提炼（有资料时，8 字段逐项）

| # | 字段 | 从哪来 | 注意 |
|---|------|--------|------|
| ① 产品定位 | 官网 hero/首页一句话 | 没人写主题就概括"卖给谁+解决什么" |
| ② 产品线 | 产品页/目录/分类 | 含子品类/SKU/成分配比；有就列，没有不编 |
| ③ 核心卖点 | 卖点文字/官网 feature | **≤5 条，每条一句**：为什么买你 |
| ④ 目标客群+市场 | 官网 About/目标客户/语言 | 国家/语言/渠道角色 |
| ⑤ 规格/认证 | 参数表/证书页 | **有来源才写**（型号/标准号/证书/日期）；无来源留空 |
| ⑥ 差异化 | vs 竞品 | 有对比写；推断⚠️标注 |
| ⑦ 合规/禁忌 | 法律/禁运区/受管制 | 有依据才写；无则空 |
| ⑧ 可引用数字 | 产能/MOQ/交期/价格带 | **用户给或官网可查才写**，没有不编 |

**来源标注（必填）**：`来自用户` / `来自官网/目录解析` / `行业合理推断⚠️`——每项都要归到其中一种。⚠️ 标推断的要请用户核对。

## 4. 状态机、确认与版本（工具硬闸门）

| 状态 | 含义 | 能否进入 S2 | 文案事实边界 |
|---|---|---|---|
| `draft` | AI 已建档/提炼，等待用户核对 | 否 | 不生成平台内容 |
| `confirmed` | 用户确认当前字段与来源，正文 hash 已锁定 | 是 | 仅引用有 source 的字段；高风险事实用 claims 绑定 |
| `declined` | 用户跳过或明确不提供资料 | 是 | 只能用无具体数字/认证/交期/价格/稀缺承诺的通用表达 |

执行入口：

```bash
python3 tools/product_profile.py init --profile runs/<operator_key>/<product_key>/product-profile.md --operator-key <operator_key> --product-key <product_key>
# AI 填写 8 字段及每项 source/confidence，用户核对后：
python3 tools/product_profile.py confirm --profile <路径> --by <纯昵称> --quote '<用户确认原话>' --summary '<本次变更摘要>'
python3 tools/product_profile.py validate --profile <路径> --require-confirmed
```

用户拒绝/撤回资料时运行 `product_profile.py decline --profile <路径> --quote '<用户原话>'`：当前8字段重置、status=declined、版本更新；若已有下游产物，operation-record进入ERROR_BLOCKED next=S2，必须重审。
已确认档案补充新资料后必须再次 confirm：版本递增、变更记录追加、旧plan/tmap/序列/S11证据失效，下游同样进入ERROR_BLOCKED next=S2。

## 5. 校验（产出后必做，防编造）

对照这台流程的硬纪律（L-50 实测入职 + 不编造）：

- [ ] 数字（产能/MOQ/交期/价格带/认证标准号）**是否都有来源**？没有的一律删或标 ⚠️
- [ ] ③卖点是否每条都**具体可感知**（不是"质量好/性价比高"这种空话）？
- [ ] ④客群是否**可批量检索**（对应 product-fit 三档的买家盘）？
- [ ] 是否有**假前提/假稀缺/漂绿**（如"我们环保"无依据）？
- [ ] 与用户一句话产品/目标市场**冲突**时，是否以用户口径为准并标注差异？

## 6. 回落（存哪、怎么调用）

- **回落位置**：`runs/<operator_key>/<product_key>/product-profile.md`。`operator_key/product_key` 创建后不可改名；跨会话/换机先读 `status/profile_version/content_sha256/updated_at/confirmed_at`。
- **确认流程**：S0a 用 `output-templates/S0-产品知识档案.md` 展示 8 字段 → 用户重点核对 ③卖点/⑤认证/⑧数字及来源 → `product_profile.py confirm` 回落版本/hash。
- **强制调用**：`flow_orchestrator.py --profile`、`gen_templates.py --profile` 均硬校验；S2/S4/S7/S9 的确认参数必须记录当前 profile path/hash/version。
  - S2 客群：读 ①②④ 的产品线/客群/市场 → 推演更准
  - S4 客户线：读 ①③④ 判断直采/OEM/拓品
  - S7 开发信：读 ③⑥ 卖点/差异化 + ⑧ 可引用数字（先给用户看再写）
  - S9 钩子：读 ③ 卖点 → 写对方视角钩子（非能力陈述）

## 7. 与对抗审查对接（★用户强制）

product-profile 属于 **S2 客群分析/种子筛选/模板文案的"知识底座"**——按 `RULES.md` 四类固定清单里的**客群分析清单**与**模板文案清单**审查（①真实性 ②每项有据 ③卖点事实可举证 ④无假前提假稀缺 ⑤首句=钩子）。审查代理须核对档案里的**数字/认证/卖点是否可溯源**，发现编造即打回。

## 8. 边界提醒

- 档案是**辅助获客的素材**，不是用户公司的全套尽调——不推导向用户索要财务/组织架构等与获客无关的敏感内部信息。
- 用户**明确拒绝**给资料 → 尊重，用行业通用口径（标⚠️）继续，不纠缠。
- **主动索取分层**：公司名/官网/联系邮箱/默认市场等公司级资料 → `operator-profile.md`；产品线/卖点/认证/产能/MOQ/交期/价格带 → 当前 `product-profile.md`。两者都供 AI 建档与分析；公司身份/联系信息不进入签名区，confirmed 且有来源的产品事实可进入正文卖点。
- **永不索要/写入产品档案（第三方信息）**：潜在买家/客户/联系人的联系方式清单、终端用户邮箱。
